## Аннотация
«Управление ключами для спутниковой связи на основе схем распределения секрета»

Проект посвящён защите сессионных ключей в LEO-созвездиях, где спутник виден 6–12 минут, а сессия постоянно передаётся между узлами. Проблема: компрометация одного спутника не должна раскрывать сессию, доверие должно быть распределённым.

Реализуем управление ключами на основе схем разделения секрета: ключ разбивается на n долей по Шамиру и раздаётся спутникам, восстановление — только при сборке k долей. Для сравнения — Блэкли и (N, N)-схема, анализ по размеру доли, времени, стойкости. Модель LEO-созвездия, шифрование AES-GCM. В работе также реализуются proactive refresh (обновление долей обнуляет многолетний сбор), VSS (ловит злого дилера), динамическое k (порог под обстановку) и пороговая подпись. Демонстрируются атаки: компрометация m спутников, злой дилер, накопление долей, подмена, replay.

Интерактивная 3D-сцена показывает орбиты, доступность долей для станции и состояние сессионного ключа. Отчёт также содержит статические графики, результаты бенчмарка и CSV.

Результат: симуляция на Python с анимацией и графиками, сравнительный анализ трёх схем, метрики стойкости и производительности.

## Проверенная локальная сборка

Четыре открытых PR объединены в ветке `integrated`. Каталог с этим README содержит исходники сборки. Клонирование `master` с GitHub загрузит версию без этих объединений. Подробный статус заданий команды и первоочередные доработки приведены в [отчёте](docs/INTEGRATION.md).

Для запуска нужны Python 3.10 и uv. В PowerShell на Windows при пути с кириллицей сначала включите UTF-8 для текущего окна.

```powershell
$env:PYTHONUTF8 = "1"
```

Из каталога этого README выполните:

```console
uv sync --locked --extra analysis
uv run --locked python -m pytest -q
uv run --locked python -m satellite_key_management.analysis.demo
uv run --locked --extra analysis python -m satellite_key_management.analysis --out results
uv run --locked satellite-key-management --out leo
```

Готовый пример можно открыть через [index.html](src/satellite_key_management/results/index.html). После нового прогона откройте `leo/index.html`. По умолчанию моделируются 120 минут. Доставка и модельные события в сохранённых экспериментах учитываются каждую минуту. Параметр `--threat` задаёт уровень угрозы для адаптивного порога и соответствующего графика.

В разделе «Орбиты и зона видимости» нажмите «Настроить сценарий». Можно менять число спутников, число плоскостей, порог, период обновления долей, орбиту и положение станции. Кнопки «Пример ниже порога» и «Пример с раскрытием ключа» загружают воспроизводимые события для текущего порога. В журнале можно добавлять, редактировать и удалять раскрытия, изоляцию и восстановление спутника, ротацию ключа и раскрытие ключа целиком.

3D-сценарий использует круговые орбиты с учётом вращения Земли. Стартовый профиль — 550 км и 53°, маска угла места — 10°. Для 3D-демонстрации выбраны 120 спутников в шести плоскостях, чтобы при пороге три показать и доступный кворум, и простои. Сохранённый орбитальный эксперимент в CSV использует собственную трассу. Кворум станции означает, что в текущую минуту геометрически доступны хотя бы `k` неизолированных спутников. Передача долей считается защищённой, а данные о раскрытии вводятся отдельно. На обеих 3D-страницах кнопка «Настроить наблюдателя» открывает долготу и широту наземного радионаблюдателя. Стартовая точка — 55° с. ш., 45° в. д. Для станции и наблюдателя действует одна маска угла места. Источники физических параметров приведены в разделе «Допущения и источники» на странице сценария. Логику интерактивного сценария можно проверить командой `node tests/test_orbit_scenario.cjs`.

Для сравнения фиксированного и адаптивного порогов запустите `uv run --locked satellite-key-management --out leo --threat 0.01`. Для короткой демонстрации можно добавить `--minutes 35 --step 2`. На странице `leo/index.html` откройте «Сравнить исходы атак». В начальной паре кворум раскрытых долей достигается без обновления и остаётся ниже порога с обновлением. Кнопка «Показать кворум до обновления» показывает границу этой защиты. Сценарии раскрытия долей задаются заранее. Видимость определяет, какие узлы доступны наземной станции. [Разбор сценариев и результаты](aihelp/attack-review.md)

Блок подписи использует пороговую BLS12-381 на базе `py_ecc` и доверенного дилера. Обновлённый API возвращает открытые параметры и доли из `generate_key(n, k)`. Координатор вызывает `combine_signs(partials, message, public)`. Прежние ключи и подписи учебного Шнорра несовместимы с этим форматом. Полная модель работает локально в одном процессе и предназначена для обучения.
